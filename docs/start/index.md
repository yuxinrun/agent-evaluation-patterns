# 阅读指南：把这本书用起来

这不是一本「从头读到尾」的书，而是一本「用到哪查到哪」的手册。但如果你完全没搭过评测，按顺序读完前六章，收益最大。

## 三层结构：同一件事讲三遍 {#structure}

每一章都按同一个节奏展开，你可以在任何一层停下：

| 层级 | 你会看到 | 适合谁 |
| --- | --- | --- |
| 第一层 · 人话 | 类比故事、`::: tip 人话翻译` 提示块、生活化比喻 | 所有人，尤其是非技术读者 |
| 第二层 · 原理 | 图解、分层表、字段表、时序图 | 开发者，需要建模与实现 |
| 第三层 · 工程 | 可直接复制的代码、阈值、避坑清单 | 要上线的人 |

::: tip 人话翻译
读不懂「轨迹评测」时，先跳到本章的「人话翻译」块：它把 Agent 的一次任务翻译成「一趟外卖配送」——不只是看有没有送到，还要看骑手有没有绕路、有没有敲错门、有没有顺手把邻居家的快递也带走。
:::

## 图例说明 {#legend}

全站图解都是手写的 SVG / CSS，不依赖图表库，缩放不失真、明暗主题都清晰。常见七种：

- **流程图**：从左到右，箭头上的小字是「这一步发生了什么」。
- **分层图**：从上到下是抽象层级，越往下越靠近数据与执行。
- **时序图**：竖线是角色，横箭头是消息；虚线表示「内部/可选」调用。
- **生命周期图**：状态与迁移，比如「发现失败 → 入库 → 回归 → 固化」。
- **对照图**：左右对比，通常一边是正确做法，一边是翻车做法。
- **中枢图**：中间一个核心，向外辐射若干组件或场景。
- **矩阵图**：场景 × 方案，或「问题 → 指标 → 阈值」的决策表。

代码块右侧有一键复制，左侧有行号；长代码可以横向滚动。**所有示例都不含真实密钥**，请把 `sk-...` 当作占位符。

## 三种阅读路径 {#paths}

### 小白 / 产品经理

目标：建立判断力，不被「我们评测跑到 96 分」这种话术唬住。

1. [第 00 章 开篇](/intro/)：Agent 评测到底在测什么。
2. [第 01 章 基础概念](/concepts/)：Run / Trace / Thread 与四类评测器。
3. [第 02 章 指标体系](/metrics/)：哪些数字值得看，哪些是自嗨。
4. [第 13 章 踩坑清单](/pitfalls/)：七种「分数好看但不可信」的典型姿势。

### 开发者

目标：两周内给现有 Agent 接上能阻断发布的评测流水线。

1. [第 14 章 Demo](/demos/)：先把最小闭环跑通。
2. [第 03 章 数据集工程](/datasets/)：没有数据集，评测就是空转。
3. [第 04 章 四大评测器](/evaluators/)：按场景挑，别硬套。
4. [第 06 章 CI 门禁](/ci/)：让坏版本进不了主干。

### 架构师

目标：把评测做成平台能力，而不是每个团队各写一份脚本。

1. [第 09 章 平台选型](/platforms/)：SaaS、自建、还是最小组合。
2. [第 12 章 线上评测](/production/)：抽样旁路，不影响主链路。
3. [第 15 章 规模化](/scale/)：队列、分层裁判、预算熔断。
4. [第 16 章 生态联动](/ecosystem/)：评测如何接进观测、网关与调度。

## 站内使用技巧 {#tips}

- **搜索**：按 `⌘K` / `Ctrl+K`，支持中英文混合，例如搜「黄金数据集」「trajectory eval」「Kappa」。
- **语言**：右上角语言按钮一键切换中英文，同一章节锚点一致，可以直接对照读。
- **主题**：右上角主题按钮切浅色/深色，默认跟随系统。
- **目录**：右侧「本页目录」跟随滚动高亮；移动端在顶部「目录」里。
- **章节跳转**：每页底部有「上一章 / 下一章」，页尾还有生态跳转。

## 内容可信度 {#sources}

本站内容基于以下公开资料与工程实践整理，示例做了简化：

- **Anthropic**：Agent 评测工程实践（Demystifying evals for AI agents）、工具设计评估、安全评测思路。
- **OpenAI**：Agents SDK 的评测与追踪、评估（Evals）产品文档中的数据集与评分器设计。
- **LangChain / LangSmith**：Agent Evaluation 概念体系、Trajectory Evaluation、数据集与实验管理。
- **开源社区**：Promptfoo（LLM-as-judge 与 CI 集成）、DeepEval、Braintrust、OpenEvals、Phoenix、Langfuse、MLflow 的评判器校准文档。
- **国内实践**：InfoQ、掘金、腾讯云与华为云等平台的 Agent 评测落地经验（以栏目与专题页引用为主）。

::: warning 关于「最新」
评测是一个模型与工具都在快速演进的领域：裁判模型每季度换代，平台 API 每半年改版。本站以「稳定的心智模型 + 可迁移的工程约束」为原则：分层评测对象、四类评测器、轨迹评分、CI 门禁、裁判校准不会过时；具体字段与阈值会变化，文中会标注假设。
:::
